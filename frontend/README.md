# Frontend «Аким на 5 часов»

React/Vite интерфейс к API v1. Все суммы и ограничения для предварительной проверки берутся из `/api/catalog`; окончательное решение о допустимости набора и Score всегда возвращает backend.

## Запуск

Из корня полного проекта в PowerShell:

```powershell
Copy-Item frontend/.env.example frontend/.env.local
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run dev
```

Открыть `http://localhost:5173`. Если backend запущен на другом порту, изменить `VITE_API_URL` в `frontend/.env.local` и перезапустить Vite. Ключ OpenAI хранится только в корневом `.env` backend и не передаётся клиенту.

## Проверка

В шапке доступен переключатель **RU / ҚАЗ / EN**. Русский выбран по умолчанию;
выбор сохраняется в `localStorage` (`akim-language`). Переводятся интерфейс,
названия мер/районов/показателей и предварительная валидация. Смена языка не
сбрасывает решения и не отправляет новый расчёт. Серверные тексты AI и описания
компромиссов показаны дословно на русском с пояснением на выбранном языке.
Словарь: `src/translations.js`; React-контекст и переключатель: `src/i18n.jsx`.

```powershell
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

Тесты проверяют правила выбора на настоящем `data/city.json`: пример из задания, бюджет, повторы, направления, конфликты и районный масштаб; также актуальность и подстановку одной замены. Сборка создаёт `frontend/dist/`.

После сборки можно выполнить `npm.cmd --prefix frontend run test:browser`: конечная проверка в установленном Edge/Chromium, без слушающего сервера и платного провайдера. Скрипт перехватывает сетевые запросы страницы и вызывает FastAPI TestClient с `AI_MODE=mock`/пустым ключом. Проверяет обязательные риски, применение каждой карточки, двойной клик, ошибку и повтор, сброс старых советов и ширину 390 px. Python берётся из `.venv`; нестандартные пути задаются через TEST_PYTHON и BROWSER_EXECUTABLE. Это не проверка публичного HTTPS-деплоя.

## Сценарий демо

1. На старте показать исходный Score 52.56 и критические S1/S2 Нуры.
2. Нажать «Рассчитать и получить AI-анализ» для набора из PDF: стоимость 95, Score 56.54, критических значений 0.
3. Показать статус `analysis.mode` и `notice`. `live` означает ответ модели или кэш; `mock` и `fallback` явно обозначены как шаблон.
4. Сохранить результат для сравнения, перенести M7 из Нуры в Есиль и рассчитать снова.
5. В блоке AI-анализа выбрать проверенную замену через «Применить». Критерии: лучший Score, минимальная стоимость среди улучшающих и минимум критических значений. Совпадающие победители объединяются с несколькими отметками. Форма изменит ровно одну меру с сохранением порядка и запросит новый расчёт. Предложения не объединяются автоматически; старые советы после изменения формы недоступны.

Все критические показатели, большой остаток бюджета и слабые места распределения уже включены сервером в risks — не фильтровать их в интерфейсе. Сильные стороны привязаны к отдельным мерам методом leave-one-out; эти вклады не складываются в общий прирост Score.

Сравнение хранит один ответ сервера в `localStorage` браузера и сверяет `dataset_version`. Сохранения сценариев на backend пока нет.
