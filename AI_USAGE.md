# Использование Codex

## 23.09.2026 — первичная архитектура

Запрос пользователя: прочитать два PDF с ТЗ и датасетом, сразу создать архитектуру и отправить в GitHub. Пользователь ранее разрешил LEAD самостоятельно коммитить и пушить.

Codex извлёк весь текст 3 страниц задания и 5 страниц датасета через pypdf, перенёс численные правила, создал спецификацию, архитектуру, контракты, backend, mock AI, стартовый frontend, скрипты проверок и задачи команды. Исходные PDF не добавлялись в репозиторий. Внешние шаблоны приложения не копировались.

Принятое решение: подробные правила датасета имеют приоритет над неоднозначным требованием «5 решений по направлениям». Разрешены минимум 3 направления при максимуме 2 мер на направление; пример организаторов этому соответствует. Вся численная модель отделена от AI.

Подтверждены базовый Score 52.55768 и пример стоимостью 95 со Score 56.54307. Контроль включает ограничения бюджета/направлений/повторов/районов, все типы конфликтов, лаги, синергии, отрицательный эффект, clip, порог строго <40, все 120 перестановок примера и независимость запросов. 32 автоматические проверки прошли; React/Vite production-сборка прошла. Серверы и браузерное демо не запускались.

Ограничения: реальная LLM, e2e браузера, публичный деплой и база данных ещё не реализованы. При AI_MODE=live каркас честно возвращает fallback. Текущая версия — основа для работы команды, не завершённый продукт хакатона.

## 23.09.2026 — живой AI-анализ

По запросу «подключай и делай дальше» Codex реализовал OpenAI Responses API через SDK 2.54.0 и Structured Outputs. Использован навык OpenAI Docs; схема вызова, разбор структурированного результата и ограничения повторов сверены с официальной документацией. Числовая сводка остаётся серверной; модель формирует качественные объяснения и гипотезы для сравнения.

Добавлены общий deadline в пределах таймаута frontend, максимум один повтор SDK, fallback с фиксированной причиной, маскирование текстовых ПДн, кэш успешных ответов на час/128 записей, конечный smoke-test без запуска серверов. Формула, каталог и зоны FRONTEND/OPS не менялись. Необязательные поля source/reason документированы, примеры обновлены. Инструкция активации находится в ai/README.md; OPS передана задача обновить описания в своих документах.

Пользователь добавил ключ в локальный .env; значение не выводилось и в Git не включалось. Первый запрос с таймаутом попытки 6 секунд вернул fallback/timeout. Небиллинговая проверка доступности модели прошла; после изменения таймаута попытки на 12 секунд при неизменном общем deadline 12 и сокращения ответа реальный запрос завершился успешно: mode=live, source=provider, reason=null, score=56.54307. Вызов скрипта занял около 7 секунд.

Проверка: 53 теста, включая реальный SDK с подменённым HTTP-транспортом, успешный и некорректный ответ, отказ, обрыв, неверный ключ, квоты, сетевой сбой, повтор, отмену по deadline, кэш и отсутствие ключей/сырых ошибок в логах. scripts/check.sh --require-frontend завершился успешно, production-сборка React прошла. Есть предупреждение Starlette об устаревании HTTPX-интеграции TestClient; на результат проверок не влияет.

Для UI нужен перезапуск уже работающего backend, затем новый расчёт. Серверы агент не запускал/не останавливал. Публичный деплой, браузерные e2e и сохранение сценариев остаются следующими задачами.

## 23.09.2026 — проверяемые факты и конкретные рекомендации

Повод: пользователь показал живой ответ с ошибочным утверждением о «трёх мерах социальной политики». В исходном наборе две социальные меры, но три меры с лагом три квартала. Запрос: доработать дальше.

Codex разделил группировку по направлениям и лагам и заменил свободный вывод модели на выбор ID готовых фактов. Structured Outputs сами по себе не гарантируют смысловую точность; с учётом официального руководства OpenAI Docs выбран более узкий формат AISelection. Модель ранжирует факты и советы, сервер проверяет принадлежность ID соответствующим категориям и сам формирует отображаемые утверждения. Неизвестные ID, дубли и свободный текст отклоняются. Версия промпта/кэша изменена на city-evidence-selection-v2.

Добавлен детерминированный перебор всех допустимых замен одного решения. До трёх лучших улучшений включаются в новый необязательный массив alternatives; каждое содержит полный набор для повторного расчёта, Score, бюджет и ухудшения показателей. Советы не применяются автоматически и не объединяются между собой. При fallback эти рассчитанные варианты также доступны. Движок формулы, исходный датасет и чужие зоны не менялись.

Проверка: 66 тестов и production-сборка frontend прошли через scripts/check.sh --require-frontend. Тесты включают наблюдавшуюся ошибку направления/лага, недопустимые ID и категории, бюджет/правила каждой альтернативы, повторный расчёт её Score, независимость порядка и отсутствие заявления о глобальном оптимуме.

Живой запрос с локальным ключом завершился mode=live, source=provider примерно за 4.7 секунды. В тексте правильно указаны соцсфера — 2 и отдельная группа из 3 мер с лагом 3 квартала. AI выбрал замену M5 в Сарыарке на M3 в Нуре: стоимость 100, Score 57.20556 против 56.54307. Компромиссы явно указаны: качество воздуха Сарыарки −8.75 и надёжность ЖКХ −2.50 относительно исходного выбранного набора. Ключ не выводился и не добавлялся в Git. Запуска серверов не было.
