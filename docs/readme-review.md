## BLOCKER-ы и замечания для LEAD

### README-PORT — конфигурация контейнера

- Где: `.env.example` задаёт `PORT=8001`, Dockerfile по умолчанию использует 8000; старая live-команда в `deploy/README.md` передаёт файл без переопределения порта.
- Воспроизведение по конфигурации: скопировать пример `.env`, запустить старую команду с `-p 127.0.0.1:8000:8000 --env-file .env`; приложение слушает внутри контейнера 8001, опубликован 8000. В этой задаче контейнер для воспроизведения не запускался.
- В README применён рабочий обход: `-e PORT=8000`. LEAD должен согласовать единый порт конфигурации; код не изменён.

### README-BROWSER — старый OPS smoke в main

- Где: `tests/e2e/browser_smoke.mjs` в исследованном main ожидает `.decision`, интерфейс использует `.decision-card` и новый ChoicePicker.
- Воспроизведение: запустить этот браузерный smoke против нового интерфейса — ожидание старого селектора не найдёт карточки. Несоответствие установлено чтением кода; новый прогон не заявляется.
- LEAD/OPS должны согласовать интеграцию и адаптацию проверки. Общий `scripts/check.py` этот браузерный сценарий не запускает; он не включён в быстрый старт README.

### README-AI-CHECK — различать кэш и новый запрос

- `scripts.check_ai` допускает успешный `live/cache`; успешный код выхода сам по себе не доказывает доступность провайдера. README отключает кэш для отдельной проверки нового ответа.
- `deploy/smoke.py --expected-ai-mode live` сверяет также health. Без ключа сохранённый `live/cache` может сопровождаться `health.ai_mode=fallback`; служебный smoke отвергнет такой корректный демо-режим. Его HTTP timeout 30 секунд также не оставляет запаса поверх общего AI deadline 30 секунд.
- LEAD/OPS: согласовать семантику проверки демо-кэша и таймаут. Код не изменён; для жюри дан контрольный сценарий через интерфейс.
