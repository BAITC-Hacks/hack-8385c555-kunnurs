Отклонение текста схемой не доказывает устойчивость настоящей LLM к prompt injection. CORS не является авторизацией. Проверка отсутствия одной строки в `caplog` не доказывает маскирование всех ПДн в инфраструктуре.

Проваленных тестов нет. Проверены API-ошибки, входные атаки, неизменность данных и локальные Python-логи. Во время сетевого прогона логи сервера/прокси не подменяются клиентским caplog: эта часть подтверждена только in-process. Заражённый внутренний датасет и настоящий провайдер остаются вне проверенного объёма. Открытые препятствия: [OPS-PUBLISH и OPS-API-KEY](blockers.md). Точные ревизии и результаты — в [статусе деплоя](deployment-status.md). Временные тестовые контейнеры удаляются после прогона.

После каждого запуска записать: дату/время, commit, режим (remote/in-process), origin без секретов, команду, passed/failed/skipped. Каждый FAIL оформить отдельным BLOCKER со входом, ожидаемым/фактическим ответом и владельцем зоны. Не публиковать секреты или реальные ПДн в отчёте.
