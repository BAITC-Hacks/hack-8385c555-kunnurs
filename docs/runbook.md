2. Выполнить `python deploy/container_check.py --build --browser` и `python deploy/container_check.py --mode fallback --browser`. Опубликовать ровно проверенный коммит, записать hash, платформу, URL и режим в `deployment-status.md`.
3. Пройти `judges-checklist.md` из другой сети. Для завершения обязательного AI-критерия нужен реальный `live`, не mock/fallback.
4. Владелец аккаунта подтверждает достаточные ресурсы/кредиты до конца 28.09, HTTPS, доступ к логам и восстановлению. Free Render имеет холодный старт; команда должна решить, приемлем ли он.
5. Зафиксировать последний рабочий релиз и инструкцию возврата к нему в панели хостинга. Автодеплой на период проверки отключить, изменения публиковать только после проверки.

## Если страница не работает

1. Проверить `/api/health` и состояние платформы. Если Free Render спал — дождаться пробуждения и повторить smoke. Не записывать неуспешную проверку как PASS.
2. Если health не восстанавливается, посмотреть build/runtime logs без раскрытия env. Проверить bind `0.0.0.0:$PORT`, start command, наличие данных и состояние ресурсов аккаунта.
3. Через Dashboard повторно развернуть последний известный рабочий коммит. Не сбрасывать Git и не делать force-push.
4. Если API работает, а UI нет: проверить `/` и `/assets/*`, сборку Vite и отсутствие localhost в запросах. Нужна пересборка образа, runtime env не переписывает bundle.
5. При 422 сверить сценарий с контрактом. При неверных числах сохранить запрос, dataset_version и ответ, оформить BLOCKER LEAD.
6. При отказе AI проверить `analysis.mode/source/reason`. `missing_api_key` — ключ не попал в контейнер; `authentication_error` — ключ недействителен; `permission_error` — нет доступа к модели; `rate_limit` — лимиты/квота; `timeout`/`connection_error` — сеть. После изменения env пересоздать контейнер через Compose `up --force-recreate`, либо выполнить redeploy на платформе. Временный `AI_MODE=mock` сохраняет расчёт; записать снижение функциональности и уведомить LEAD через человека.
7. После восстановления выполнить smoke и ручной расчёт 95 / 56.54. Записать время начала/конца сбоя, причину и hash восстановленного коммита.

Сервис не хранит пользовательские сценарии. Для текущего MVP восстановление сводится к образу, версии данных и env; резервная копия БД не требуется. API-ключ хранится в секретах платформы, не в отчётах.
