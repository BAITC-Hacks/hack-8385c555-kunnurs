# Инструкции для агентов проекта

## Контекст

Проект «Аким на 5 часов», HackAlem AI, Management. Три участника, каждый со своим клоном, веткой, Git-аккаунтом и агентом. Координация через людей и файлы, а не прямые сообщения другим участникам. Приоритет: работающее демо, обязательные критерии, затем расширения.

Прочитать SPEC.md, TASKS.md и contracts/api.md перед предметными изменениями. Источники правил: SPEC и предоставленный датасет, не догадки LLM. Score считает только детерминированный backend. Секреты не выводить; брать из .env.

## Владение

- LEAD, main: contracts/, backend/, ai/, scripts/, .githooks/, requirements.txt, SPEC.md, TASKS.md, AGENTS.md, AI_USAGE.md, .gitignore, .gitattributes, .env.example.
- FRONTEND, feat/frontend: только frontend/.
- OPS, feat/ops: data/, tests/e2e/, deploy/, docs/, README.md.

Первичный каркас всех зон создан LEAD по прямому запросу пользователя. После передачи команде LEAD не редактирует чужие зоны: получает изменения через интеграцию веток. Контракты, SPEC и TASKS изменяет только LEAD. Доступ роли lead ко всем файлам в Git-хуке нужен для интеграции и не отменяет разделение работы.

## Git и проверки

Пользователь явно разрешил основному LEAD-агенту самостоятельно коммитить и пушить в командный репозиторий BAITC-Hacks/hack-8385c555-kunnurs. Это заменяет исходный запрет из первого промпта. Не подменять авторство других участников. Не выполнять destructive reset, force-push или массовый откат без отдельной необходимости и согласования.

Перед задачей и в итоговом отчёте проверять `git log -1 --format="%cr — %s"` и `git status -sb`. Во время активного хакатона напоминать о коммите после 30 минут и интеграции после 45 минут. Пушить рабочую версию не реже раза в час. Не делать пустые коммиты ради таймера. Проверки перед коммитом: `python scripts/check.py --require-frontend` (или wrappers scripts/check.sh / check.ps1). Исправления минимальные, без массового форматирования.

Не запускать долгоживущие процессы: uvicorn, vite, npm run dev и watch. Пользователь запускает серверы в собственных терминалах. Допустимы конечные pytest, импорт приложения, npm run build. Хук проверяет роль из `git config team.role`; установить `git config core.hooksPath .githooks`.

## Запросы и интеграция

CONTRACT_REQUEST, DEPENDENCY_REQUEST и BLOCKER оценивать относительно демо и критериев. Изменения API обратно совместимые; одновременно обновлять схемы, примеры, документацию и тесты. Сообщить, что поменялось и кому что исправить. Зависимости/формулы/стоимости не менять без причины из требований.

Ревью чужой ветки по запросу: `git diff main...origin/feat/frontend` либо `git diff main...origin/feat/ops`. Проверить зону, контракт, секреты, баги и интеграционные риски. В рамках запроса только на ревью ничего не исправлять. Вердикт: БЛОКЕРЫ / МОЖНО МЕРЖИТЬ / МЕЛОЧИ.

После задачи: что сделано, затронутые файлы, проверка, риски/остаток работы, статус commit/push. Обновлять AI_USAGE.md содержательными фактами; никаких выдуманных проверок. Не выдавать mock/fallback за живой AI и локальную сборку за публичный деплой.
